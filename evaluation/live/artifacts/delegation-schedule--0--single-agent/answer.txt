```json
{
  "schedule": [
    {"task": "A", "worker": "w1", "start": 0},
    {"task": "B", "worker": "w2", "start": 2},
    {"task": "C", "worker": "w1", "start": 2},
    {"task": "D", "worker": "w1", "start": 5},
    {"task": "E", "worker": "w2", "start": 5}
  ],
  "makespan": 7,
  "stale_completion": "reject",
  "recovery": "reclaim-new-version",
  "handoff": ["A", "4", "api.py", "test_api"]
}
```

**Rationale:**

**Schedule:** A runs first on w1 (0-2), enabling C to start on w1 (2-4). B runs on w2 (2-5) to avoid overlap with A. At time 5, D (depends on B@5, C@4) runs on w1 (5-6) and E (depends on B@5) on w2 (5-7). Makespan = 7.

**Stale completion:** Reject. The old worker's version 4 is stale; the replacement already produced version 5. Accepting it would overwrite newer work.

**Recovery:** Reclaim-new-version. Since we reject the old submission, we keep the replacement's valid work from the new lease (version 5).

**Handoff:** Identifies the artifact (api.py) with contention between A and B, the old lease version (4), and corresponding tests.
