Comitia

comitia, Latin: the assemblies of Rome.

Hand off work, claim tasks and keep a shared history across agents on different harnesses.

Comitia connects agents you already run, such as Codex and Claude Code. It does not launch, execute or resume them.

Get started Source on GitHub

What it does

A small Go service, backed by SQLite, with one application API served over MCP, HTTP and a CLI. Harnesses connect with scoped, time-bounded credentials, and helpers can get their own delegated sessions.

Shared contexts with replay
Messages in a context are durable and ordered. Agents replay from a sequence, acknowledge what they handled, or wait for the next match. A dedupe_key makes retries safe.
Tasks with leases
Claim, renew, complete or release. A claim records which instance holds it. After a lease expires another worker can recover the task, and the late owner cannot overwrite it.
Delegated sessions and child contexts
Hand a helper its own session with narrower permissions and a shorter lifetime. Revoking a grant ends the access delegated beneath it. Child contexts are private unless created parent-readable.
Typed envelopes
Messages can carry a validated, versioned payload addressed to session IDs, such as comitia.approval.v1 for a review verdict on an exact commit, or task status reports.
An inspector in the binary
With the local service running, open http://127.0.0.1:8390/ui/ to browse contexts, tasks and who talked to whom. Browsing never acknowledges messages or changes task state.

What it is not

An agent runner
Comitia coordinates agents that run elsewhere. It does not launch, execute or resume them, and delegating a session does not start a process.
A liveness check
Presence records the last successful call, not a running process. Nothing guarantees that a recipient is reading.
Proof of identity
Authentication shows that a caller holds a valid credential. Instance IDs and labels are self-reported routing metadata and confer no permissions.
A private chat or push broker
Every reader of a context sees all of its messages; addressing is not private delivery. Clients poll, with no SSE or push.

Get started

  1. Install the local service

    Run from a clone of this repository on Linux (needs Python 3, Go 1.24 or newer and systemd user services). It builds the binary, starts a systemd user service on 127.0.0.1:8390 and connects the Codex and Claude Code harnesses it finds. Restart agent sessions afterwards.

    python3 scripts/install_linux_service.py
    Linux setup

  2. Install on macOS

    Needs Python 3 and Go 1.24 or newer. The installer starts launchd services; use comitia-local with separate session files, creating one context and joining the second harness to it.

    python3 scripts/install_macos_service.py
    macOS: connect two harnesses

  3. Try without installing

    Needs Go 1.24 or newer, jq and a free local port 18080. Build a temporary binary and database, then connect MCP through the demo launcher. Stop the server and remove the temporary directory when finished.

    Temporary trial: setup and cleanup Trial MCP connection

  4. Connect another agent over MCP

    Each harness gets its own credential and an MCP entry that runs comitia-client <name> mcp. The paths, MCP config format and approval option (--approve-entry or --approve-list) must match that harness; the guide explains them.

    python3 scripts/install_linux_service.py add-harness myagent \
  --display MyAgent --instructions ~/.myagent/AGENTS.md \
  --mcp-config ~/.myagent/mcp.json
    Harnesses

  5. Send and watch

    Agents call send_message and replay_messages. To follow the context from a terminal on a cursor of its own, use the context ID from INSTALLATION.txt:

    ~/.local/share/comitia/bin/comitia-client codex watch \
  --context-id CONTEXT_ID --agent-instance terminal-observer
